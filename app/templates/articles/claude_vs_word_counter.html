Which one to use

  • The Word Counter website, for a quote or a client report. It’s free, uses no AI at all, and it’s where you sign in to a site, leave folders out, download the text of every page, and put a client’s sites together in one project.
  • Your assistant connected to Word Counter, when you’re already working in Claude or ChatGPT. You get the same count, and an assistant that reads it with you: what to quote on, what to leave out, which section is biggest.
  • An assistant on its own, for a handful of pages, or a count with rules of your own, such as only the product descriptions. Then a script written for the occasion is the point.

Why ask an assistant at all?

“How many words does our website have?” is the first number in every website translation quote, and the first question in most migration and content audits. More and more, it’s typed into an AI assistant instead of a tool. So we tried it, with the assistant most likely to get it right: Claude Code, Anthropic’s agentic tool, which can browse, run shell commands and write its own programs.

The site was wxrks.com — ours. It’s a good test: a Webflow site with a long blog, a mega-menu on every page, and complete translations into {{ x.languages }} languages. Its sitemap lists {{ n(x.sitemap_urls) }} addresses.

How we ran it

  • Claude Code {{ x.claude_code }}, model {{ x.model }}, on {{ x.run_date }} — non-interactive, with the full log of every step kept.
  • A new, empty folder for every run: no memory, no project instructions, no MCP servers except the one being tested.
  • The same permissions every time — fetching web pages, web search, curl, wc and python3 — what you’d approve if Claude asked. Spending caps of $5 for the quick question and $8 for the careful one.
  • Two questions. The quick one: “How many words does the website wxrks.com have?” The careful one: “I need an accurate word count of the entire website wxrks.com for a translation quote: every page, the total number of words, how many pages there are, and how much of the text is repeated across pages. Count it as accurately as you can.”
  • Then both again with Word Counter’s MCP server connected — a copy running the same code as {{ counter_surface.host }}, at the free plan’s speed — and nothing else changed.
  • Times and costs are Claude Code’s own figures. Costs are at API prices; on a Claude subscription the same work comes out of your usage limits instead.

Why the numbers differ

1. Menus and footers, on every page

A one-off script counts every word in a page’s HTML. On wxrks.com that includes a mega-menu and a full footer — {{ cm.median_extra }} words, at the median — on all {{ n(aq.pages) }} pages. Word Counter opens each page in a browser and counts the main content: menus, footers, sidebars and forms are left out of each page — they get translated once, not once per page. Where a site builds its footer without the HTML that says so, as Webflow does here, the leftover links show up as the report’s most repeated text (1,047 times) — counted once as new, and as repetition everywhere else.

2. What a visitor actually sees

Raw HTML includes text a visitor never sees: in Round 1, Claude’s script noted that Webflow hides elements with display:none — and counted them anyway; in Round 2 it spent much of its hour deciding what to do about them. On many sites raw HTML also misses text that only arrives with JavaScript (wxrks.com renders on the server, so not here). Word Counter counts the page after it has loaded, as a visitor would read it.

3. Repetition

A translation quote prices repeated sentences differently from new ones. Word Counter splits every page into sentences and found {{ wf.repeated_pct }}% of the words repeating text from other pages — the CTAs, the disclaimers, the blocks reused across posts. {{ x.alone_repetition_why }}

4. Where the site actually ends

A sitemap lists what its owner remembered to list. wxrks.com’s doesn’t include its help center, its developer docs, its community or eight other subdomains — {{ n(wf.subdomain_words) }} words between them. Word Counter follows the links a visitor could follow, across the whole domain, and the report shows each subdomain on its own line, so leaving one out of a quote is a decision, not an accident. (You can also ask it to count one host only.)

5. The language you translate from

wxrks.com is already translated into {{ x.languages }} languages: {{ n(x.translated_pages) }} of its {{ n(x.sitemap_urls) }} addresses are translations. A quote counts the source, so Word Counter detected English and set the translated versions aside without fetching them, naming each one in the report. Claude, left to itself, set about crawling all {{ n(x.sitemap_urls) }} — and in Round 2, after fetching them, it rightly said the English count is the basis for the quote.

6. Time and money

Building and running a crawler cost Claude {{ dur(aq.seconds) }} and {{ usd(aq.cost) }} for the quick question{% if ac %}, and {{ dur(ac.seconds) }} and {{ usd(ac.cost) }} for the careful one{% endif %} — and the next site starts from zero again. With Word Counter the crawl runs on Word Counter’s servers and Claude spends its tokens on the question and the answer: {{ usd(wq.cost) }} for the estimate. Following a 35-minute count cost {{ usd(wf.cost) }}, nearly all of it Claude re-reading the conversation at each of its {{ wf.checks }} checks — asking once more at the end would cost cents.
